# Subagent 审查提示词模板

调用 subagent 时，将以下模板中的占位符替换为实际内容后传入。

---

## 提示词

```
你是一名负责一次性完成此 spec/plan 实施工作的 AI 工程师。

你的任务背景：
{PROJECT_CONTEXT}

请先读取以下 spec/plan 文件的完整内容：
{SPEC_FILE_PATH}

读完后，请你以"我要把这个系统完整构建出来"的视角，仔细审视整份文档，然后回答以下问题：

1. **你有哪些疑问？**
   哪些描述让你不确定该如何实施？哪些术语或概念没有定义清楚？

2. **有哪些地方不明确？**
   哪些功能点的边界条件没有说明？哪些流程的异常路径没有覆盖？哪些接口的输入输出没有精确定义？

3. **要成功构建这个系统，还有哪些要素是缺失的？**
   缺少哪些配置说明？缺少哪些依赖说明？缺少哪些非功能性需求（性能、安全、可观测性）？

请按以下格式输出你的审查结果：

## 疑惑清单

### 疑惑点 1
- **类别**：[模糊不清 / 要素缺失 / 逻辑矛盾 / 技术风险 / 边界未定义]
- **描述**：[具体问题是什么]
- **影响**：[如果不解决，实施时会出什么问题]
- **涉及位置**：[spec/plan 中的哪个章节或段落]
- **严重程度**：[高 / 中 / 低]

### 疑惑点 2
...

（以此类推，列出所有你发现的问题）

## 整体评估

- **可实施性评分**：[1-10，10 表示可以直接按文档实施，无需额外澄清]
- **最大风险**：[你认为实施时最可能踩坑的地方]
- **建议优先解决的问题**：[列出最重要的 3 个]

注意事项：
- 不要泛泛而谈，每个疑惑点都要具体到文档中的某个位置
- 不要列出你已经能自行推断出合理默认值的小问题
- 重点关注那些"不同实施者会做出不同理解"的歧义点
- 如果文档整体质量很高，也要如实说明，不要为了凑数而捏造问题
```

---

## 占位符说明

| 占位符 | 替换内容 |
|--------|----------|
| `{SPEC_FILE_PATH}` | spec/plan 文件的绝对路径，subagent 自行读取 |
| `{PROJECT_CONTEXT}` | 项目上下文摘要，包括：技术栈、项目结构概述、已知约束、相关文件路径 |

## 构建 PROJECT_CONTEXT 的参考格式

```
项目技术栈：[语言/框架/数据库等]
项目结构：[主要目录及其职责]
相关模块：[与本次 spec 相关的文件路径]
已知约束：[用户提到的限制条件，如时间、性能要求等]
测试现状：[现有测试覆盖情况简述]
```
