## 审查清单

**代码质量:**
- 关注点是否清晰分离？(Clean separation of concerns)
- 是否有适当的错误处理？
- 类型安全（如适用）？(Type safety)
- 是否遵循 DRY 原则？
- 边界情况是否处理？(Edge cases)

**架构:**
- 设计决策是否合理？
- 是否考虑可扩展性？
- 性能影响如何？
- 是否存在安全隐患？

**测试:**
- 测试是否真正测试逻辑（而非仅测试 mocks）？
- 边界情况是否覆盖？(Edge cases)
- 需要集成测试的地方是否包含？
- 所有测试是否通过？

**需求:**
- 是否满足所有计划需求？
- 实现是否匹配规范？
- 是否存在范围蔓延？(No scope creep)
- 破坏性变更是否记录？

**生产就绪性:**
- 迁移策略（如涉及 schema 变更）？(Migration strategy)
- 是否考虑向后兼容性？(Backward compatibility)
- 文档是否完整？
- 是否存在明显 bug？

## 关键规则

**要做的:**
- 按实际严重程度分类（不要把所有问题都标记为严重）
- 要具体（file:line，不要模糊）
- 解释为什么问题重要
- 承认优势
- 给出明确结论

**不要做的:**
- 不检查就说"看起来不错"
- 把琐碎问题标记为严重
- 对未审查的代码给出反馈
- 含糊其辞（如"改进错误处理"）
- 避免给出明确结论
