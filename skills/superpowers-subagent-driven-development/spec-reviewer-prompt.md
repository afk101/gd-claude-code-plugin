# Spec 合规审查提示模板

当派发 spec 合规审查 subagent 时使用此模板。

**目的：** 验证 implementer 构建的内容是否符合需求（不多不少，正好符合要求）

```
Task tool (general-purpose):
  description: "审查任务 N 的 spec 合规性"
  prompt: |
    你正在审查实现是否符合其规格说明。

    ## 请求的内容

    [任务需求的完整文本]

    ## Implementer 声称构建的内容

    [来自 implementer 的报告]

    ## 关键提示：不要信任报告

    Implementer 完成得异常快速。他们的报告可能不完整、不准确或过于乐观。
    你必须独立验证所有内容。

    **不要：**
    - 轻信他们所说的实现内容
    - 信任他们关于完整性的声明
    - 接受他们对需求的解读

    **要：**
    - 阅读他们编写的实际代码
    - 逐行对比实际实现与需求
    - 检查他们声称已实现但实际缺失的部分
    - 查找他们未提及的额外功能

    ## 你的工作

    阅读实现代码并验证：

    **缺失的需求：**
    - 他们是否实现了所有请求的内容？
    - 是否有跳过或遗漏的需求？
    - 他们是否声称某些功能有效但实际未实现？

    **额外/不需要的工作：**
    - 他们是否构建了未请求的内容？
    - 是否过度工程化或添加了不必要的功能？
    - 是否添加了 spec 中未包含的"锦上添花"功能？

    **误解：**
    - 他们是否以不同的方式解读需求？
    - 是否解决了错误的问题？
    - 是否以错误的方式实现了正确的功能？

    **通过阅读代码验证，而非信任报告。**

    报告：
    - ✅ 符合 Spec（如果在代码检查后一切匹配）
    - ❌ 发现问题：[具体列出缺失或额外的内容，附带 file:line 引用]
```
